# /lw-branch：整个分支汇总

范围是**整个分支相对基准分支的全部改动**。只想看后期改动用 `/lw-report`。参数：`$ARGUMENTS`（Claude Code 会替换成命令后面的文字；Codex 等工具里不替换，就取用户消息里命令名后面的内容，没有就是空）（`pr` = 额外输出 PR 描述）

`LW = python3 ~/.light-work/lw.py`

## 1. 取材料

```bash
$LW check --branch --hunks 10
$LW conflicts
$LW stats
```

读台账全文（`.light-work/<分支>.md`）。功能主体的结构，按 check 输出的文件列表去读代码。先按 /lw-check 的逻辑把全部约束判一遍。

## 2. 写报告（Markdown，按这个结构）

````markdown
# feature/voice-search · 分支汇总
> 一句话：新增语音搜索（识别 → 搜索 → 结果/空/错误三态），之后 7 次变更，整体 L3
> 约束核对：14 条，✓ 12 ｜ ✗ 0 ｜ ? 2
> 需要你：拍板 2 项；review 建议 15 分钟，按下面的阅读顺序

## 这个分支做了什么
- 功能本身：3~5 条要点（从代码和分支 diff 归纳）
- 后期变更：按主题归并（不是逐条罗列），每个主题标条目 ID

## 整体架构 / 流程
（mermaid：模块之间的调用关系或主流程时序；本分支新增的节点和后期改过的节点用不同样式，
 classDef added 新增，classDef changed 后期修改；节点标条目 ID）

## 阅读顺序（≤8 步，从入口到细节）
1. `文件:行` — 为什么先看

## 文件清单
| 文件 | 作用 | 新增/修改 | 关联条目 |

## 风险
- 敏感区域、热点、回退、跨模块接口变化、未登记改动，每条带依据

## 待拍板

## 给测试的回归清单
| # | 场景 | 操作步骤 | 期望结果 | 来源 | 优先级 |
（覆盖：功能主流程、台账里每条有效约束、未验证项；按 P0/P1/P2 排）

## 未验证汇总
````

## 3. 生成页面

把上面的报告 Markdown 直接通过标准输入交给脚本，不要另存文件：

```bash
$LW view --title "分支汇总" --open <<'LW_REPORT'
（上面写好的报告全文）
LW_REPORT
```

页面是 `.light-work/<分支>.html`（每次生成都覆盖），末尾自动附上台账原文。在聊天里只回三行结论和页面路径。

## 4. 参数为 `pr` 时

在聊天里另外输出一段可以直接粘贴的 PR 描述：一句话总结、改动要点、测试清单（P0/P1）、风险。不出现台账编号和内部过程。

## 规则

片段只取真实 diff，图只画真实存在的模块和函数，最上面三行是结论。
